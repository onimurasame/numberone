How Everything in Number One Works

Every subsystem in numberone is built on real cryptographic primitives, strict POSIX file confinement, pure functional replay, and deterministic verification — zero mocks, zero cloud lock-in, and zero prompt theatrics.

1. Cryptographic Stream & CAS Blobs (StreamStore)

All workspace occurrences append to .numberone/stream/events.jsonl (mode 0o600 inside 0o700 .numberone/) serialized under PID-tick-verified advisory locks (linkSync + /proc/<pid>/stat).

  • Monotonic ULIDs: 48-bit ms timestamp + 80-bit CSPRNG entropy with within-ms monotonic increment.
  • Canonical SHA-256 Chain: Sorted-key canonicalJson links prevHash -> hash from GENESIS_HASH and flushes via fsyncSync.
  • Linear-Time Secret Scrubbing: AWS, GitHub, Slack, Anthropic, OpenAI, Google, Stripe, JWT, PEM, Bearer/Basic, URL userinfo, and SAS tokens are redacted before disk write.
  • Content-Addressed Blobs: Large diffs, snapshots, and crash logs are stored once at .numberone/fallback/blobs/<sha256>.blob.

2. Deterministic Replay & Digest Guard (ReplayEngine)

Current state (WorkspaceProjection, version 3) is a pure mathematical fold (applyEventToProjection) over the atomic event stream.

  • O(1) Verified Cache: projections/state.json embeds a canonical SHA-256 snapshotDigest verified against stream/head.json on every read.
  • Time-Travel Forensics: Replay exact state at any historical moment via n1 replay --until-seq N or --until-timestamp ISO.
  • Workspace Documentary: n1 documentary compiles raw events into narrative session chapters across harnesses and people.

3. L1–L4 Authority & Memory (AuthorityEngine)

Number One supersedes ephemeral chat prompts whenever session context conflicts with verified institutional history.

  • Precedence: L1 SoR Stream & Crashes > L2 Number One Directives > L3 Officer Gates & Verified Lessons > L4 Session Context.
  • Affirmative Clause Parsing: Strips negated compliance clauses ("do not use eval") to eliminate false-positive blocks while catching real violations.
  • Auto-Lesson Correlation: n1 exec automatically links prior crashes and edited files to synthesize lesson.captured when tests turn green.

4. BMAD Party Mode & KPI Evolution (src/crew/)

Three specialist officers audit live workspace files and evolve their rulebooks strictly through empirical proof.

  • Engineering, Security & Bridge Officers: Measure runtime_readiness_score, security_posture_score, and continuous_delivery_score (0..100).
  • Round 2 Challenge Verification: Peer challenges are adjudicated against check telemetry as CONFIRMED, REBUTTED_BY_EVIDENCE, or ESCALATED.
  • KPI-Proven Self-Evolution: Candidate practices promote if and only if counterfactual virtual-file replay proves delta > 0 and 0 false positives.

5. Hardened stdio MCP & Live Sensors

Connects natively to any MCP client while capturing manual terminal and IDE activity in the background.

  • NumberOneMcpServer: Exposes 12 tools & 4 numberone:// resources with 2 MB pre-decode line limits, stdin backpressure, and strict L4 privilege guards.
  • Universal Sensors: WorkspaceFsWatcher, chained worktree-safe Git hooks, bash/zsh crash hooks, and JSONL/Markdown transcript ingestion.

6. Distributed Scrum Persistence Fabric

Mirrors issues, lessons, directives, ADRs, crashes, and rulings across Scrum platforms while keeping .numberone/ whole at all times.

  • Adapters: Zero-SaaS Directory/Worktree Kanban, GitHub Issues + Projects v2 GraphQL (including GHES), and Jira REST v3 + ADF + Agile Sprints.
  • SSRF & Credential Origin Guard: resilientFetch blocks RFC 1918, loopback, CGNAT, and 169.254.169.254 metadata IPs and binds env tokens strictly to origin.
