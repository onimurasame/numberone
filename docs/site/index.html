Part 1 · Plain-English Guide (Zero Jargon Required)

How Number One Works, in Everyday Words

Whether you are a student, parent, teacher, writer, designer, or engineer, here is the complete picture of what Number One does for your project folder — without needing a computer science degree.

Before The "Goldfish Memory" Problem

  • Chats reset and forget: You spend an hour explaining your project rules to an AI helper, and tomorrow a fresh chat starts completely blank.
  • Broken ideas come back: A teammate or new AI window suggests the exact same thing that already failed yesterday.
  • Only the final files survive: Looking at a finished project never tells you why you chose one design over another.
  • Accidental mistakes slip through: It is easy to accidentally leave a password in a note or forget to double-check your work before sharing.
  • Writing the final report is painful: At the end of a project, you have to dig through messy folders trying to remember everything you did.

With Number One One Calm, Un-Erasable Project Memory

  • Every tool shares the same notebook: Switch computers, open a brand-new AI chat, or hand off to a teammate — Number One briefs them in seconds.
  • Failed tries stay remembered: Dead-ends and past fixes are saved clearly so nobody wastes time repeating old mistakes.
  • Your rules always stay in charge: Important project ground rules override forgetful chat guesses automatically.
  • Built-in safety nets: Passwords and secret keys are automatically hidden before notes hit disk, and three helpers inspect your work on demand.
  • Instant project story & time machine: Generate a clean chapter-by-chapter project documentary or rewind to see any earlier moment.
SUPERPOWER 01

The Self-Writing Project Diary

Just like a scientist's bound lab notebook where pages are never torn out, Number One quietly logs your file edits, ideas, choices, and test results in a tidy hidden folder (.numberone/) with a tamper-evident seal on every entry.

SUPERPOWER 02

The "Don't Repeat That" Shield

Every time you try something that flops — or fix a tricky problem — Number One saves the lesson. Next time you (or an AI assistant) work on that same area, Number One immediately surfaces what went wrong before and how you fixed it.

SUPERPOWER 03

Rules That Outlast Chat Resets

Write down a simple rule once (like "keep keyboard controls working" or "never put passwords in files"). Even if an AI chat forgets your conversation, Number One steps in and stops conflicting plans before they happen.

SUPERPOWER 04

The Automatic Secret Hider

Before writing any note, log, or file snapshot, Number One automatically scans for things that look like passwords, access tokens, or private keys and masks them out — keeping private secrets out of your project history.

SUPERPOWER 05

A Time Machine & Storyteller

Curious what your project looked like at step #5? Number One can replay history to any exact moment. Ready to share or hand in your work? One command turns raw notes into a neat, chapter-by-chapter Project Documentary.

The 4-Step Rulebook Ladder

Whenever a brand-new AI chat says one thing, but your project history says another, Number One settles the tie using four simple levels — highest level always wins:

  1. LEVEL 1
    What Actually Happened (Real Facts) Unfixed crashes and verified facts in your project diary always come first — nobody can pretend a broken test passed. (Technical name: L1)
  2. LEVEL 2
    Your Project's Ground Rules Important "must-follow" or "never-do" rules you or the helpers set for your folder. (Technical name: L2)
  3. LEVEL 3
    Lessons & Decisions You Already Made Past discoveries, saved fixes, and group decisions explaining why the project is built this way. (Technical name: L3)
  4. LEVEL 4
    Today's Chat Guess Suggestions from a fresh AI chat window — helpful, but always checked against Levels 1–3 first! (Technical name: L4)

How Everything in Number One Works

Every subsystem in numberone is built on real cryptographic primitives, strict POSIX file confinement, pure functional replay, and deterministic verification — zero mocks, zero cloud lock-in, and zero prompt theatrics.

60-Second Engineering Quick Start

Install globally on Node.js >= 22.0.0, attach to any workspace, watch live changes, and run a 3-officer BMAD Party Mode audit.

bash · quick-start 
npm install -g @onimurasame/numberone
cd /path/to/your/workspace
n1 attach .
n1 watch
n1 brief
n1 party --topic "Production, security & continuous delivery readiness"

3.1 Physical .numberone/ Layout, POSIX Confinement & Advisory Locking

When n1 attach . runs, StreamStore.init() initializes a confined .numberone/ hierarchy at the workspace root with owner-only permissions (0o700 / 0o600):

.numberone/ physical directory layout 
.numberone/                       # Mode 0o700 (owner rwx only)
├── config.json                   # Mode 0o600 — NumberOneConfig (mode, watcher, persistence, crew, llm)
├── daemon.pid                    # Detached watcher PID + Linux /proc/<pid>/stat field-22 startTicks
├── daemon.log                    # Background watcher operational log (gitignored)
├── stream/
│   ├── .stream.lock              # Cross-process advisory lockfile serializing stream appends
│   ├── head.json                 # Mode 0o600 — Atomic StreamHead { lastSeq, lastEventId, lastHash, updatedAt }
│   ├── events/
│   │   ├── 00000001-<ULID>.json  # Mode 0o600 — Immutable SHA-256 hash-chained StreamEvent files
│   │   └── 00000002-<ULID>.json
│   └── blobs/
│       └── <sha256>              # Mode 0o600 — Content-addressed snapshots, full diffs & crash logs (n1://fallback/<sha256>)
├── projections/
│   └── state.json                # Cached WorkspaceProjection guarded by canonical snapshotDigest (gitignored)
└── sync/
    ├── .sync.lock                # Cross-process advisory lockfile serializing persistence pushes
    └── ledger.json               # Mode 0o600 — Bidirectional mapping between event ULIDs and remote IDs
  • Symlink Escape Prevention (src/utils/fs-helpers.ts): Every read and write verifies isPathConfinedToRoot / isWritablePathConfinedToRoot via fs.realpathSync and opens descriptors with fs.constants.O_NOFOLLOW where supported, neutralizing symlink-swap TOCTOU (CWE-59/CWE-367) attacks.
  • Crash-Safe Atomic Writes (atomicWriteFileSync): Writes to a unique sibling temporary file (O_CREAT | O_EXCL), flushes kernel page buffers via fs.fsyncSync(fd), applies 0o600 mode bits, and atomically replaces the target via fs.renameSync.
  • PID-Reuse-Safe Advisory Locks (src/utils/lock.ts): Concurrent writers (n1 watch, IDE n1 mcp, post-commit hooks) serialize via atomic fs.linkSync (with wx fallback), zero-CPU Atomics.wait sleep, and single-FD O_RDONLY | O_NOFOLLOW stale-lock checks against process.kill(pid, 0) and field 22 (starttime ticks) of /proc/<pid>/stat.

3.2 Cryptographic Append-Only Event Stream (StreamStore)

Every workspace occurrence is recorded as one of 47 typed StreamEvents (src/core/types.ts).

  • Monotonic ULID Assignment (generateUlid): 26-char Crockford Base32 ULID combining a 48-bit millisecond timestamp with 80 bits of crypto.randomBytes entropy; increments monotonically within the same millisecond.
  • Fail-Closed Tip Verification (getHead): Cross-checks stream/head.json against the tail event in stream/events/. Self-heals only when a crash wrote the exact next valid chained event; fails closed with Stream integrity violation on corruption or tampering.
  • Canonical SHA-256 Hash Chaining: Event #1 sets prevHash = "0".repeat(64) (GENESIS_HASH); event #k links prevHash = event[k-1].hash using recursively sorted canonicalJson (blocking __proto__, constructor, prototype). Remote sync refs live in sync/ledger.json so pushing later never mutates event hashes.
  • Full Chain Verification (n1 verify): Validates Zod schemas, contiguous seq = 1..N, unbroken prevHash -> hash links, head.json parity, and every referenced blob digest.

3.3 Linear-Time Secret Redaction & CAS Fallback Blobs

Before any StreamEvent or text BlobRef touches disk, redactSecrets and redactObjectDeep (src/utils/redactor.ts) scrub credentials in guaranteed O(n) linear time.

  • Scrubbed Token Classes: AWS keys (AKIA*, ASIA*), GitHub PATs (ghp_*, github_pat_*, gho_*, ghs_*, ghu_*), Slack tokens (xox[baprs]-*) & webhooks, Anthropic (sk-ant-*), OpenAI (sk-*), Google (AIza*), Stripe live/restricted keys, 3-part JWTs, PEM private keys, HTTP Authorization headers, URL userinfo, generic password/token KV pairs, and Azure SAS signatures.
  • Sensitive Filename Suppression (isSensitiveSecretFile): .env* (except .env.example/.sample/.template), *.pem, *.key, *.p12, *.pfx, id_rsa*, id_ed25519*, .npmrc, .pypirc, .netrc, and .aws/credentials are metadata-tracked without snapshotting raw contents.
  • Content-Addressed Storage (storeBlob): Large command logs, diffs exceeding maxInlineDiffBytes (16 KB), and snapshots store once at .numberone/stream/blobs/<sha256> addressed via n1://fallback/<sha256>.

3.4 Deterministic Replay, Snapshot Digests & Time-Travel (ReplayEngine)

ReplayEngine (src/core/replay-engine.ts) implements pure functional event sourcing with zero external side effects.

  • Pure Reducer (applyEventToProjection): Deterministically folds all 47 event types without reading wall-clock time, randomness, or live disk state.
  • Tamper-Evident Cache Guard (computeProjectionDigest): projections/state.json embeds projectionVersion: 3 and canonical SHA-256 snapshotDigest. getCurrentState() uses the O(1) cache only when lastSeq, lastEventHash, and recomputed snapshotDigest all match; any drift triggers full replay from seq #1.
  • Forensic Time-Travel: Run n1 replay --until-seq 25 or n1 replay --until-time 2026-11-23T09:05:00Z to inspect exact workspace state at any historical point without mutating current state.

3.5 Authoritative Precedence (L1–L4) & Affirmative Arbitration (AuthorityEngine)

Resolves conflicts between ephemeral chat assumptions and institutional truth via strict four-tier precedence (src/core/authority-engine.ts):

  • Precedence Ladder: L1_SOR_INVARIANT (immutable stream facts & unresolved critical crashes) > L2_NUMBER_ONE_DIRECTIVE (active blocking/mandatory/advisory directives & Party Mode vetoes) > L3_OFFICER_GATE (officer directives, verified high/critical lessons & active ADRs) > L4_SESSION_CONTEXT (ephemeral AI prompts).
  • Affirmative Clause Analysis: extractAffirmativeClauses strips pure negated compliance clauses ("never call eval(") while catching mixed affirmative clauses ("instead call eval(input)").
  • ReDoS Immunity (validateRegexSafety): Rejects nested quantifiers, overlapping alternations, backreferences, and lookbehinds so patterns execute in linear time.
  • Verdicts: APPROVE (exit 0), APPROVE_WITH_CONDITIONS (exit 0), OVERRIDE (authoritative guidance override), and BLOCK (exit 2).

3.6 Institutional Memory & Crash-to-Fix Lesson Synthesis (LessonEngine)

LessonEngine (src/core/lesson-engine.ts) stops teams and AI harnesses from repeating solved failures.

  • Multi-Signal Lesson Scoring (findRelevantLessons): Exact path match (+6), directory prefix (+3), error-signature substring (+8), tag overlap (+4), normalized keyword overlap (+1..+5), verification bonus (+2), and severity weighting.
  • Dead-End Shield (findRelevantFailedAttempts): Surfaces prior attempt.failed records touching the same files or problem space before work begins.
  • Automatic Failure-to-Fix Correlation: When n1 exec transitions from exec.failed/exec.crashed to exec.completed (exitCode === 0), scans the causal window for edited paths and dead ends, resolves the crash, and auto-synthesizes a lesson.captured event.
  • Workspace Documentary (n1 documentary): Compiles chronological session chapters across harnesses, people, crashes, and rulings.

3.7 Live Workspace Sensors: Watcher, Daemon, Git Hooks, n1 exec & Transcripts

Captures manual IDE saves, Git operations, terminal crashes, and offline AI chats continuously.

  • WorkspaceFsWatcher: Honors .gitignore + .numberone via linear-time WorkspaceIgnore, coalesces burst writes (debounceMs: 250), computes bounded unified diffs, snapshots text into CAS blobs, and supports n1 reconcile for offline edits.
  • WatcherDaemonManager: Detached background n1 watch daemon binding daemon.pid to Linux /proc/<pid>/stat start ticks and flushing cleanly on SIGTERM/SIGINT.
  • Chained Git Hooks: Uses git rev-parse --git-path hooks (worktree & custom core.hooksPath safe) and chains post-commit, post-checkout, post-merge, post-rewrite, and pre-push without overwriting Husky/Lefthook.
  • runWatchedCommand & ingestTranscriptFile: Strips secrets from child envs (buildSanitizedChildEnv), captures UTF-8-safe bounded ring buffers, escalates timeouts (SIGTERM -> SIGKILL), installs bash/zsh crash hooks, and imports Claude/Codex JSONL, JSON, and Markdown transcripts.

3.8 Model Context Protocol (stdio MCP) & L4 Privilege Boundary

NumberOneMcpServer (src/harness/mcp-server.ts) implements MCP 2024-11-05 over stdio JSON-RPC 2.0 with zero external SDK dependencies.

  • Memory & Pipe Hardening: Enforces maxLineBytes = 2,000,000 on raw Buffer chunks prior to UTF-8 decoding, pauses stdin for async backpressure, and traps stdout EPIPE cleanly on IDE disconnect.
  • Strict L4 Privilege Boundary: (1) record_stream_event allows only non-privileged telemetry types (chat.turn, chat.thinking, attempt.failed, issue.opened, issue.updated, decision.recorded); (2) issue_directive over MCP is capped at severity: 'advisory'; (3) propose_officer_evolution unconditionally locks allowBenchmarkExec: false.

3.9 BMAD Party Mode Bridge Crew (Engineering, Security & Bridge Officers)

SecurityOfficer		 security_posture_score Hardcoded credential scanning (cleanly skipping test fixtures & shell echoes), .gitignore secret hygiene, lockfile integrity, dangerous code sinks (eval, new Function), GitHub Actions 40-char commit SHA pinning & least-privilege permissions:, non-root containers, SECURITY.md, and Dependabot/Renovate (OWASP ASVS, SLSA, NIST SSDF).

  • Round 1 — Independent Telemetry Assessment: Inspects real workspace files & WorkspaceProjection, producing weighted checks, concrete OfficerFinding[], and cross-officer PeerChallenge[] (persisted as crew.opinion + officer.kpi.measured).
  • Round 2 — Deterministic Peer Challenge Verification (resolvePeerChallenges): Adjudicates every challenge against real telemetry as CONFIRMED, REBUTTED_BY_EVIDENCE, or ESCALATED.
  • Round 3 — Precedent Correlation, Matrix & Veto Ruling: Correlates findings with historical lessons & dead ends, emits OfficerDecisionRow[] + prioritized P0–P3 RemediationItem[], and emits crew.consensus (exit 0) or crew.veto (exit 2) with an automatic active L2 blocking directive on critical defects.

3.10 Empirically Verified KPI-Gated Continuous Evolution (KnowledgeEvolutionEngine)

Officers upgrade their rulebooks without hallucination or prompt drift via src/crew/evolution-engine.ts:

  • Safety Gate: Candidate practices must pass KnowledgeUpdateProposalSchema and linear-time validateRegexSafety.
  • Counterfactual Virtual-File Proof (counterfactual_replay): Evaluates labeled compliant (expectedViolation: false) and violating (expectedViolation: true) virtual file maps via evaluatePracticeMatcherOnVirtualFiles. Promotes if and only if 100% of compliant samples pass (0 false positives) and KPI discrimination strictly improves (delta > 0).
  • Live Regression Auditing & Rollback: n1 evolve audit <role> flags live KPI drops (>= threshold), and n1 evolve revert <role> <practiceId> deactivates regressed practices via officer.knowledge.reverted.

3.11 Distributed Scrum Persistence Fabric

PersistenceFabric (src/persistence/fabric.ts) synchronizes work items bidirectionally while keeping .numberone/ always integral:

  • .numberone/ Primary Fallback: Oversized crash logs, thinking arrays, and binary blobs remain local and link via n1://fallback/<sha256>.
  • Directory / Worktree / NFS Adapter: Zero-network JSON + Markdown Kanban across backlog/, in-progress/, blocked/, done/, lessons/, directives/, decisions/, and board.md.
  • GitHub Issues + Projects v2 (and GHES): Auto-provisions 14 n1:* labels, embeds lossless HTML5-safe <!-- n1-meta:{...} --> footers, syncs Projects v2 GraphQL Single-Select Status columns, and supports custom apiBaseUrl.
  • Jira Cloud & Data Center: Formats descriptions in Atlassian Document Format (ADF), tags officer components (n1-engineering, n1-security, n1-bridge), binds to Agile Sprints, and pulls edits via JQL.
  • Hardened HTTP Transport (resilientFetch): Blocks SSRF against RFC 1918, loopback, CGNAT, and cloud metadata (169.254.169.254), binds tokens strictly to HTTPS origin (resolveScopedEnvVar), caps response payloads, and retries 429/502/503/504 with Retry-After + jittered backoff.

GitHub Platform Governance & Security Automation

Complete GitHub security, supply-chain verification, and Pages publishing automation ships out of the box:

  • CI & Hardened Container Verification: .github/workflows/ci.yml
  • GitHub Pages Interactive Docs + Archify Deployment: .github/workflows/pages.yml
  • CodeQL SAST Analysis: .github/workflows/codeql.yml + .github/codeql/codeql-config.yml (0 alerts across first-party TS/JS/HTML)
  • Supply-Chain Dependency & License Review: .github/workflows/dependency-review.yml & .github/dependabot.yml
  • Dependabot PR Triage, Provenance & Batch Merge: .github/workflows/dependabot-triage.yml, scripts/verify-workflows.mjs & scripts/pr-automation.mjs validate 40-char SHA pins, github/codeql-action/* lockstep, commit signatures, upstream tag-to-SHA provenance, and Pages bundle completeness.
  • Signed Provenance Releases: .github/workflows/release.yml
  • Automated Repository Provisioner: scripts/configure-github.sh provisions Pages, Issues, Discussions, Projects v2 board, 21 labels, milestones, Dependabot/Secret Scanning, and Branch Rulesets.
bash · governance & provisioning commands 
# Preview or apply GitHub API provisioning
./scripts/configure-github.sh --repo onimurasame/numberone --dry-run
./scripts/configure-github.sh --repo onimurasame/numberone

# Verify workflow SHA pins, CodeQL lockstep & Pages bundle locally
npm run verify:workflows

# Dry-run Dependabot PR policy triage, or approve & squash-merge eligible green PRs
npm run pr:triage
npm run pr:merge
